01 · 市场与机会国内外市场与渠道能从目标地区、安装工程和渠道看产品组合。

中国：整案与单品是两条交付路径

以华为鸿蒙智家、米家和海尔三翼鸟做样本。整案先看房型、布线、点位、签约与验收。单品路径看用户现有网关、上墙或免布线、门店安装与售后覆盖。三者的渠道与品牌能力需逐城市确认。

美国：零售加专业服务

关注 Apple Home、SmartThings、Alexa、Google Home。门铃、温控、电工产品先查住宅适配和安装责任。产品页、专业安装、退换、无线与数据支持期要一起比。

德国及欧盟：区分法规与真实渠道

DACH 项目可把 KNX TP/IP 当工程参照。零售阶段记录国家、语种、插头/面板、房租限制、售后责任和认证资料。欧盟法规适用要按产品分类检查。韩国用 ThinQ ON 作首发与区域限定个案。

市场信号的口径

ASHB 的 611 人样本覆盖美国、加拿大，成本与设置障碍可以转成访谈题。Pew 的设备使用数据、NIST 的隐私研究各有分母。渠道上新、平台用户总量与单品销售量分别记录。

02 · 市场与机会用户场景与需求证据能把“智能一点”改写成任务、触发、失败与验收。

按人、空间和生命周期切分

区分安装者、管理员、家人、访客、物业。记录装修、后装、试用、掉线、转让。采购人、每日使用人、维护人可能不同。

记录最近一次真实行为

请用户回放实际路径：触发、做法、失败、找谁处理、耗费时间与钱。重现一次断网或权限变更，先记录事实。厂商演示可作为对照，论坛个案可设计测试。

形成可证伪需求

用“当我在书房久坐，希望灯保持亮，离开后及时关闭”替代“上毫米波”。实测误关次数、离房释放 P95 和安装分钟，并对照 PIR＋延时。

03 · 连接与架构协议、组网与选型能按网络层、应用层、生态层解释同一个连接方案。

先区分七个词

Wi-Fi / Ethernet 承载 IP，Thread 提供低功耗 IPv6 网络，Matter 定义跨设备应用层。Zigbee 自有网络及设备模型。BLE 可用于配网和近端交互，Bluetooth Mesh 是独立网络规范。平台 App 和云则负责特定体验。

小电池与大流量分开

按钮/门磁先核低功耗和现有网关。市电插座、网关先核持续连接。摄像机先核吞吐、布点、上传及本地录像。前装总线按施工、维护与点位验收比较。

不要把角色写在一个框里

Border Router 做 Thread 与其他 IP 网络互通，Controller 建立或控制 Matter fabric，Bridge 映射其他协议的设备与属性。一个物理产品可以有多个角色。

配网失败分层排查

先看复位和广播，再看账号区域、手机权限及二维码。进入网络后排查频段、IPv6、发现和路由。最后验证设备类型、集群和目标 App 实际支持。

04 · 连接与架构通讯模组与射频验证能完成方案 A/B 对比和样品评估。

确定输入与淘汰条件

把协议、区域、功耗、可用 IO、连接并发、外置天线需求、安装位置、量产成本与软件维护期列成约束。电池设备用事件占空比估算，再用实际电流曲线复核。

选 SoC、模组或双处理器

ESP32-C6 可作为带 Wi-Fi、BLE、802.15.4 的开发参考。Nordic、Silicon Labs 可评估低功耗 802.15.4 路径。摄像或中控屏通常还要另评估图像/应用处理器。具体并发依赖芯片、SDK 和配置。

报价与交付

05 · 连接与架构生态协议与认证互操作能解释“支持 Matter”具体能做什么。

从设备类型走到动作

先核标准设备类型与目标版本，再列必需属性、事件和指令。空调、摄像机、窗帘和能源能力各自核目标 ecosystem，可用功能随固件、地区与账号变化。

原生接入、桥接与云接入

原生 Matter 是设备直接进 fabric，桥接由中枢暴露端点与子集。云到云可支持扩展功能，但需承担账号、地区、断网与 API 维护成本。

多平台与权限边界

Multi-Admin 用于多个生态控制同一设备。要实测共享配网、状态同步、移除某个生态、所有权交接和完全复位。摄像画面、录像、通知和远程访问分别验收。

兼容测试矩阵

行用设备类型×功能，列用平台×地区×固件×中枢。区分标准支持、认证、厂商声明与实测。营销表述对应验证结论。

06 · 感知与系统人体与环境传感器能从目标信号和安装制约选传感器。

人体移动与存在

PIR 适合通过和低功耗触发，静止任务需明确保灯逻辑。毫米波可观察微动，仍须验证风扇、门外串扰、多径、宠物和安装高度。ToF 适合测距离或划区，遮挡、光照与窗口需实测。

环境量与派生量

直接测得 CO₂ 与从 VOC 推算的 eCO₂ 分开。温湿度看热源、进气、响应和凝露，空气质量看粉尘、采样路径、清洁设计与维护。门磁看安装间隙和偏移，漏水看探针污染、低电量与故障识别。

把误报和漏报拆开

以房间、事件和时间窗口为分母记录。独立测进门响应、久坐误关、空房误保持与离房释放 P95。测基线、干扰情形及房间迁移性。

融合与功耗

候选方案可以用低功耗移动唤醒加短时雷达确认，或用门磁和超时融合。用可断开原型测空闲、判定、上报和低温电压；按实际模式核算续航。

07 · 感知与系统典型硬件与执行器架构能从设备框图看清电源、感知、通信和执行。

通用框图

传感或按键 → MCU/SoC 与策略 → RF 或总线 → 网关/控制器 → 执行器。并行考虑电源、存储、状态指示、调试口、量产治具和身份写入。

开关与窗帘

区分单火/零火、负载类型、漏电流导致灯具闪烁等问题。设计流程先与电气工程师核负载和适用标准。窗帘核轨道、行程校准、卡阻、停电后行为和维修入口。

门锁与摄像机

08 · 感知与系统App、网关、云与 OTA能画端—网关—云—App 状态机和责任边界。

本地规则与远程能力分开

常用开关、临近控制、状态联动优先考虑有可验证本地路径。远程查询、通知和账户服务可使用云；用断 WAN 验证动作，别把断路由或断电当同一故障。

设备状态与命令

定义设备 ID、reported/desired 状态、序列号、幂等标识、时间戳、重试、冲突顺序与超时。App 区分已发送、已确认和离线未知。手动操作和重新联网要更新实际状态。

OTA 与售后

签名校验、按批发布、兼容清单、升级中断恢复、版本追溯、失败暂停和工单链接。把可回退与防回滚的策略边界分别列在安全评审里。

10 · 产业设计与交付可靠性、DVP&R 与失效闭环会定义条件、样本和判据，而不是只写“通过”。

失效从任务开始

智能灯的风险可能是进入时不亮、久坐误关或离房无法复位。门锁和市电产品按危害严重度及标准要求优先评审。用 DFMEA 将故障影响、原因、检出与行动关联。

四组测试条件

环境（温湿、凝露、振动）、结构（跌落、寿命、拉拔）、电子/RF（电源、静电、弱网）、系统（并发、断网、断电、OTA）。条件、抽样和执行由实际产品及实验室确认。

EVT / DVT / PVT 的证据

EVT 消除关键方案风险，DVT 压实规格和可靠性，PVT 关注工艺和良率。保存批次、版本、波形、日志、工单、重测结果和变更记录。

售后复现到关闭

版本化复现脚本，追踪批次与组件。优先确定影响范围与人工兜底，再判断软件修复、物流返修、换件、标识或产品变更。

填一页 DVP&R 与 DFMEA 主表。覆盖闸口、样本条件、判据、责任人、未通过复现和关闭证据。

11 · 产业设计与交付地区合规、安全与隐私能建立市场准入确认表并保留证据。

中国、美国、欧盟分别判定

中国按工信部无线电与认监委目录确认型号和用途。美国按 FCC 设备授权及整机和模组使用条件核验。欧盟按 RED 和实际产品适用法规做判定；结论由合规和实验室确认。

欧盟联网安全与英国 PSTI

CRA 第 14 条自 2026-09-11 适用，法规一般适用日期为 2027-12-11，另有分阶段条款。英国 PSTI 有独立适用范围与联网产品要求。按 SKU、地区和上市日逐条确认。

检测认证、生态认证与隐私

生态互操作认证与无线、电气、隐私合规是不同路径。对摄像、语音等产品建立数据流图，说明本地/云、管理员/访客权限、保留和删除机制。

支持周期和发布资料

量产前确认标签、说明书、软件与物料版本。上市后维护更新支持承诺、问题报告入口和批次追溯。

14 · 市场与机会品类机会与技术路线图能从待验证需求向可交付产品推进。

需求与技术两个时间轴

需求侧记录可付费的任务和渠道。技术侧记录方案能力、可验证的量产约束与平台门槛。标准发布时间、集成排期和规模量产分别标记。

产品类别先看替代线

用户坚持手动或既有自动化时，先量化其成本。传感器可做标准件，房间套装可把灯控和调试变成付费交付，整案的成本结构不同。

用门槛决定顺序
